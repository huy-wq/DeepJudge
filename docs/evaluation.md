# 系统验证与效果评估

> 目的：让"系统好不好用"成为**可量化、可复现**的结论，而不是演示几个案例。
> 答辩最容易被问的两句是"你怎么证明它准"和"它和老师差多少"——本文档就是答案。
>
> 注意：这是**验收与效果验证**，不是研究实验。不追求算法层面的新发现，
> 但必须有数据说明：与朴素做法相比，这套设计改进了什么、代价是什么。

## 1. 验证目标

这些是"设计是否成立"的待验证项，用来支撑设计取舍，不是学术假设。

| 编号 | 待验证的问题 | 验证方式 |
| --- | --- | --- |
| V1 | 采分点结构化评分是否比"直接打分"更稳定 | 对比 B0/B1 与 B2 的 QWK、重复测量标准差 |
| V2 | 证据接地校验是否真能拦住编造 | grounding rate、人工抽检编造率 |
| V3 | 多采样聚合 + 校准是否缩小了与教师评分的差距 | 校准前后 MAE / QWK |
| V4 | 模型档位与采样次数如何影响成本与效果 | 按题型分层统计（档位待定） |

## 2. 数据

### 2.1 来源与分层

- 来源：课程真实试题与答卷（脱敏授权）＋ 公开数据集补充；数据未到位时先用自建样例跑通链路。
- 题型分层（每层不少于 30 条）：简答、论述、案例分析、计算过程（含步骤分）、编程题。
- 每题配 1 份权威评分标准，转换为 architecture.md 3.2 节的 rubric schema。

### 2.2 标注规范

- **双人独立评分 + 第三人仲裁**（分歧 > 满分 10% 时触发）。
- 标注粒度：总分 + **逐采分点命中情况**（这是校准与 grounding 评估的前提）。
- 标注前用 5 份样例做校准培训，记录标注者间一致性作为**人类上限**。

### 2.3 规模与划分

| 用途 | 规模 | 说明 |
| --- | --- | --- |
| 开发/调试 | 30~50 条 | 调提示词、调 schema，可反复看 |
| 校准/验证集 | 150~300 条 | 拟合校准映射与选阈值；样本不足则不启用校准 |
| 测试集 | 100~150 条 | **不参与任何调参**，只报一次 |
| 稳定性测试 | 30 条 × 10 轮 | test-retest |

划分按**题目**分层，同一题目的不同答案不能跨集合，避免泄漏。

## 3. 指标体系

分五层，每层 2~4 个指标，避免堆砌。

### 3.1 准确性（与人工分的一致性）

| 指标 | 含义 | 备注 |
| --- | --- | --- |
| **QWK**（二次加权 Kappa） | 与人工评分的一致性，教育测量领域标准指标 | 主指标；对"差 1 分"的惩罚小于"差 3 分" |
| MAE / RMSE | 平均绝对误差 / 均方根误差 | 直观，便于答辩解释 |
| Pearson / Spearman | 线性 / 秩相关 | 看整体趋势 |
| 极端误差率 | 分差绝对值 ≥ 2 的样本占比 | 比平均值更能反映"灾难性错误" |

QWK 计算前需把连续分按 0.5 或 1 分粒度离散化，离散粒度要写进测试报告。

### 3.2 一致性（重复评分稳定性）

- **ICC(2,1)**：同一答案多次评分的组内相关系数。
- 总分标准差（R=10 轮）。
- 逐采分点一致率：n 次采样中 level 完全相同的比例。

### 3.3 可解释性与可靠性

- **grounding rate**：通过证据定位校验的判定占比（本系统的核心可靠性指标）。
- 编造率：人工抽检 100 条判定，统计证据与原文不符的比例。
- schema 合规率、重试率、空响应率。

### 3.4 效率与成本

- 单份评分平均时延（P50 / P95）。
- 单份 token 与费用（区分缓存命中 / 未命中）。
- **自动通过率**与"自动通过样本中的人机一致率"——这两个数必须一起报，只报通过率没有意义。

### 3.5 可用性（可选）

- 诊断信息准确率：系统指出的"未掌握知识点"与教师判断的一致率。
- 分数分布合理性：与人工分布的形状对比（KS 检验）。
- 复核界面的操作耗时：教师处理一份待复核答卷的平均时间。

## 4. 对照组：与朴素做法比

不是为了学术消融，而是为了回答"这个设计多出来的复杂度值不值"。
B0 是必须存在的对照组——否则无法证明系统不是"包了一层 API"。

| 编号 | 配置 | 对应验证 |
| --- | --- | --- |
| B0 | 零样本：只给题目 + 参考答案，让模型直接给分 | 最朴素基线 |
| B1 | 自然语言评分标准整段塞入，直接给总分 | 常见"提示词工程"做法 |
| B2 | rubric 结构化，逐采分点判定，**不做**证据校验 | V1 |
| B3 | B2 + 证据接地校验 | V2 |
| B4 | B3 + 多采样（n=3）聚合 | V3 前半 |
| B5 | B4 + 分数校准 + 阈值路由 | V3 后半（完整系统） |

可变因素：

- 模型档位：待接入后确定（至少两档，用于成本-效果对比）
- 采样参数：以实际 API 支持为准（若模型忽略 `temperature`，需说明稳定性从何而来）
- few-shot：0 / 2 / 5 条
- 采样次数：1 / 3 / 5

## 5. 统计处理

工程课题不必强上显著性检验，够用即可：

- 主指标给 **bootstrap 95% 置信区间**（1000 次重采样），成本很低，建议做。
- 对照组之间比较用**配对检验**（Wilcoxon），报告效应量；样本量小时只报描述统计 + 区间。
- 多组比较做 Holm 校正，避免把噪声当结论。
- 明确报告样本量；差异不显著就不要写成"提升"。

## 6. 人类基线

教师之间的 QWK / MAE 是本系统的**参照系**：人机一致性接近人际一致性，就足以支撑"可辅助评分"的结论。
这一栏几乎必然会被问到，务必提前算好。

## 8. 伦理与合规

- 答卷脱敏后方可进入模型调用；不向第三方传输可识别个人信息。
- 学生知情同意与数据用途说明；提供退出机制。
- 自动评分结果**仅作辅助**，最终成绩由教师确认（系统保留人工终审权）。
- 审计日志保存调用与复核记录，支持追溯。

## 9. 可复现性

- 每次运行固定：rubric 版本、prompt 版本、模型名、参数、采样次数。
- 采样有随机性 → 报告多次运行的均值与区间，而不是单次结果。
- 测试脚本与结果表（CSV）入库；原始答卷与大文件不入库。
