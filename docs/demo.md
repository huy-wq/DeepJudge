# 10 分钟演示脚本（答辩 / 验收）

> 目标：从登录到复核，完整走一遍「生成标准 → 导入答卷 → 评分 → 复核改分」，并能在
> **模型不可用**时退到预置数据，而不是现场卡住。
>
> 演示数据全部是合成的：答卷里没有姓名、学号，脱敏编号使用 `S-DEMO-*`。
> 不要用真实学生答卷替换演示文件。

## 0. 演示前准备（不计入 10 分钟）

```bash
# 1) 库 + 表结构 + 两份离线复核数据
./scripts/demo.sh reset          # 会清空本地演示库；首次可用 up + seed
# 2) 后端（另开终端）
cd backend
ADMIN_PASSWORD=demo-pass-2026 python3 -m uvicorn app.main:create_app --factory --port 8000
# 3) 前端（另开终端）
cd frontend
npm run dev                      # http://127.0.0.1:5173
```

没有 Docker 时用 SQLite 代替：

```bash
export DATABASE_URL="sqlite:////tmp/deepjudge-demo.db"
rm -f /tmp/deepjudge-demo.db
cd backend && python3 -m alembic upgrade head
python3 scripts/seed_demo.py --database-url "$DATABASE_URL"
ADMIN_PASSWORD=demo-pass-2026 DATABASE_URL="$DATABASE_URL" \
  python3 -m uvicorn app.main:create_app --factory --port 8000
```

`./scripts/demo.sh seed` 会写入两份预置结果：

| 脱敏编号 | 分数 | 路由 | 用途 |
| --- | --- | --- | --- |
| `S-DEMO-01` | 5.0 | `human` | 复核队列里演示证据高亮 + 改分 |
| `S-DEMO-02` | 3.5 | `auto` | 自动通过页签演示批量通过 |

两份都没有真实身份信息；`data/samples/demo/answers.csv` 只有「题号,答案」两列。

## 1. 时间线

| 时间 | 步骤 | 你要做的 | 预期现象 |
| --- | --- | --- | --- |
| 0:00–0:40 | 登录 | 打开 5173，输入 `demo-pass-2026` | 进入首页；刷新仍保持登录 |
| 0:40–2:40 | 生成标准 | 新建标准，填题干/满分/原话 → 生成草稿 | 摘要、预览表、校验清单同屏；保存后跳到 `/rubrics/{id}` |
| 2:40–4:10 | 导入答卷 | 选 Q-01，上传 `data/samples/demo/answers.csv` | 预览 4 行、带学号 0 行、重复 1 行；导入 3 份、跳过 1 份 |
| 4:10–6:10 | 评分 | 勾选新导入的 3 份，采样 1 次（或 3 次）→ 开始评分 | 进度自动刷新；任务号进 URL；失败项可见可重试 |
| 6:10–8:50 | 复核改分 | 打开 `S-DEMO-01`，点证据 → 高亮；改 4.5 + 意见 → 定稿 | 原文对应片段高亮；定稿后显示最终分与意见；返回队列已移除 |
| 8:50–9:40 | 批量通过 | 切“自动通过”页签，勾选 `S-DEMO-02` → 批量通过 → 确认 | 确认框写明份数；确认后队列移除 |
| 9:40–10:00 | 收尾 | 回首页，一句话总结 | 三步入口与设计边界 |

## 2. 逐步输入与预期

### 2.1 生成标准

新建标准（`/rubrics/new`），填写：

| 字段 | 输入 |
| --- | --- |
| 题干 | `简述 TCP 三次握手的过程，并说明其目的。` |
| 满分 | `10` |
| 评分标准原文 | `三个要点：客户端发 SYN 给 3 分；服务器回 SYN+ACK 给 4 分；客户端回 ACK 给 3 分。与四次挥手混淆扣 2 分。` |
| 参考答案 | 从 `data/samples/tcp-handshake/rubric.json` 的 `reference_answer` 复制；或留空 |

点 **生成草稿**。预期：

- 摘要一句话说明这道题在考什么；
- 预览表出现 3 个采分点（权重合计 10）和 1 个扣分项；
- 校验清单没有红色阻断项；若有黄色提示，勾“已知悉”后才能保存。

点 **保存**。预期：跳到 `/rubrics/{id}`；列表里能看到这道题的最新版。
如果模型给出的权重合计不是 10，页面会显示差额并禁用保存——**不要现场改数字硬存**，
直接说明“系统不允许保存不自洽的标准”，然后用预置标准继续。

### 2.2 导入答卷

进入 **导入与评分**（`/grading`），题号选 `Q-01`，来源选“批量 CSV”，
上传 `data/samples/demo/answers.csv`（文件会自动预览）。

预期：

- 共 4 行；带学号 **0** 行；重复 **1** 行；坏行 0 行；
- 预览表不出现任何姓名或学号（文件里本来就没有学号列）；
- 点 **确认导入**：成功提示“已导入 3 份，跳过 1 份重复”。

### 2.3 发起评分

在第二步勾选刚导入的 3 份（`S-0001`–`S-0003` 之类；**不要勾 `S-DEMO-*`**，
它们是预置结果），每份采样 1 次（演示时间优先；要讲稳定性就选 3 次）。

点 **开始评分**。预期：

- 任务卡片出现，状态从“排队中”到“评分中”再到“已完成”；
- 每份显示状态、模型分、路由；失败项会显示原因，可单份或整批重试；
- 地址栏变成 `/grading?task=N`，刷新还能接上；
- 任务头显示“标准版本 #N”：这一批固定的是启动时那一版。

如果一份失败：指出“单份失败不拖垮整批”，点重试即可；不要重跑整批。

### 2.4 复核改分（核心 3 分钟）

进入 **复核**（`/review`），默认“待人工复核”。预置的 `S-DEMO-01` 会在这里
（5 分，原因是“总分接近及格线边界”）。

1. 点 **打开**，看到逐条判定、采样等级、证据与原文；
2. 点 P1 的 **证据**（“客户端首先发送 SYN 报文”），原文对应片段变黄高亮；
3. 在右侧“改分”填 `4.5`，意见填 `P2 只写到 SYN+ACK，未说明同意接收`；
4. 点 **改分并定稿**。预期：显示“已定稿：4.5 分（改分）”，表单收起；
5. 点左上 **返回复核队列**。预期：`S-DEMO-01` 已从队列消失。

要强调的两个点：

- 原分 5.0 没有被覆盖，详情里同时保留原分与最终分；
- 改分必须写意见；分数没变化时按钮不可用，避免“改了但没改”的假记录。

### 2.5 批量通过

切到 **自动通过（待定稿）** 页签：

1. 勾选 `S-DEMO-02`（以及现场自动通过的结果，可选）；
2. 点 **批量通过（N 份）**；
3. 确认框写明“将把选中的 N 份自动通过结果按模型原分定稿”；
4. 点 **确认通过**。预期：提示已通过，队列移除。

## 3. 模型故障时的降级路径

触发条件：没有 `DEEPSEEK_API_KEY`、429、超时、连续空响应，或现场网络不通。

**不要现场重试十次，也不要伪造一个“实时评分”结果。** 按下面走：

### 方案 A：直接从复核开始（推荐，2 分钟）

```bash
./scripts/demo.sh seed      # 若库已被前面的演示写过，先 ./scripts/demo.sh reset
```

然后只演示 **复核页**：队列 → 打开 `S-DEMO-01` → 证据高亮 → 改 4.5 → 定稿 →
返回队列；再切自动通过页签批量通过 `S-DEMO-02`。

这段用的是真实前端、真实 API、真实数据库，只是评分结果是预置的。
讲解时明确说：“这是离线预置的评分结果；模型故障时我们退到复核，不假装刚调过模型。”

### 方案 B：命令行离线演示（可选，1 分钟）

```bash
cd backend
# 标准生成：预置模型输出
python3 scripts/gen_rubric.py --stem "简述 TCP 三次握手的过程，并说明其目的。" --total 10 \
    --standard "三个要点：客户端发 SYN 给 3 分；服务器回 SYN+ACK 给 4 分；客户端回 ACK 给 3 分。" \
    --response ../data/samples/tcp-handshake/generation.json

# 单份评分：预置模型输出
python3 -m app.cli --rubric ../data/samples/tcp-handshake/rubric.json \
    --answer ../data/samples/tcp-handshake/answer.txt \
    --response ../data/samples/tcp-handshake/response.json --samples 1
```

预期：前者打印摘要/预览表/校验清单；后者打印逐点等级、证据偏移、总分与路由。
这能证明引擎本身不依赖网络。

### 降级时明确跳过的部分

- 不演示“生成标准”的模型调用；
- 不演示“导入 → 发起评分”的模型调用（可只演示导入预览，证明查重与脱敏）；
- 复核与批量通过**照常演示**，因为它们不需要模型。

## 4. 演示后重置

```bash
./scripts/demo.sh reset
```

它会删库、迁移、重新写入两份演示结果。下一场演示从干净状态开始。

## 5. 可能被问到的问题（一句话版）

| 问题 | 回答 |
| --- | --- |
| 这和直接让模型打分有什么区别？ | 模型只出逐点等级与证据，分数由服务端算；证据要能回原文定位；低置信转人工。对照实验脚本在 `scripts/experiment.py`。 |
| 证据高亮能证明判得对吗？ | 不能。它只证明“引用了原文”，不证明“判定正确”；正确性要靠采分点定义与人工复核。 |
| 为什么满分/接近及格线要转人工？ | 边界分后果最重；系统宁可多一次复核，也不把边界分直接定稿。 |
| 标准改了，历史成绩会变吗？ | 不会。结果落库后不重算，明细自带当时的 rubric 快照。 |
| 为什么不能导入 Excel？ | 本期只解析 UTF-8 CSV/文本；`.xlsx` 需另存为 CSV。 |
| 有学生端吗？ | 没有。教师导入、脱敏编号，不落真实姓名学号。 |
| 多采样一定更准吗？ | 只压随机误差，压不了系统性偏差；E1 的方差实测有边界说明。 |
